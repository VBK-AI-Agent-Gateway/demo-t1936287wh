# 论文验证系统 · 多维度学术诚信检测平台 — 完整设计方案

> **定位**：从"传统查重"升级为 **引用真实性 × 文本原创性 × 图像完整性 × 逻辑/元数据一致性** 四维验证，所有结论必附可解释证据链，三级判定（通过 / 需人工复核 / 高风险）。

---

## 0. 设计原则（约束映射）

| 约束 | 设计落点 |
|---|---|
| 判定必须可解释 | 每个引擎输出 `evidence[]`，融合层结论必须回链证据 ID；报告层只渲染"证据→结论"链 |
| AIGC/图像结果仅作"信号" | 二者不直接触发"高风险"，只贡献 `signal_score`；高风险必须有人工复核入口 |
| 流程异步化、支持大文件/批量 | 提交即返回 `task_id`，Celery/Redis 队列分片处理，支持 ZIP/批量任务组 |
| 外部服务可替换 | 策略模式 + Provider 抽象接口，配置化选择（Crossref/OpenAlex/CNKI、GPTZero/内部模型…） |
| 四层架构 | 接入解析层 → 检测引擎层 → 融合决策层 → 报告接口层 |

---

## 1. 四层架构

```
┌─────────────────────────────────────────────────────────────────┐
│ ④ 报告接口层   REST API / Webhook / PDF·HTML 报告 / 人工复核工作台  │
├─────────────────────────────────────────────────────────────────┤
│ ③ 融合决策层   证据聚合 → 加权融合 → 规则引擎 → 三级判定 + 解释生成  │
├─────────────────────────────────────────────────────────────────┤
│ ② 检测引擎层   引擎注册表(可插拔)                                  │
│   E1 引用真实性   E2 文本原创性   E3 图像完整性   E4 逻辑/元数据    │
│   （每引擎：输入→流程→算法→输出{score,confidence,evidence[]}）    │
├─────────────────────────────────────────────────────────────────┤
│ ① 接入解析层   上传(PDF/LaTeX/MD/BibTeX) → 解析 → 规范化IR → 存储   │
│    Parser: GROBID / LaTeX-Parser / pandoc / bibtex-parser          │
│    产出: sections, sentences, refs, figures, tables, metadata      │
└─────────────────────────────────────────────────────────────────┘
        ①②③ 全部跑在异步任务队列(Celery)  ④ 为同步 HTTP 层
```

**规范化中间表示（IR）** 是四层解耦的关键：所有引擎只消费 IR，不关心原始文件格式。

```json
// DocumentIR（示意）
{
  "doc_id": "doc_9f31",
  "metadata": {"title": "...", "authors": [...], "venue": "...", "year": 2024},
  "sections": [{"idx": 1, "title": "Introduction", "paras": [{"id": "p1", "text": "..."}]}],
  "sentences": [{"id": "s1", "section": 1, "text": "...", "cites": ["r1", "r2"]}],
  "references": [{"id": "r1", "raw": "[1] ...", "title": "...", "doi": "10....", "venue": "...", "year": 2020}],
  "figures": [{"id": "f1", "path": "img/f1.png", "w": 800, "h": 600, "caption": "...", "cited_by": ["s9"]}],
  "equations": [], "tables": [],
  "parse": {"ok": true, "confidence": 0.97, "engine": "grobid-0.8"}
}
```

## 2. 检测引擎层（逐引擎规格）

> 统一输出信封：`EngineResult = {engine, version, score∈[0,1], confidence∈[0,1], signal_only, signals, evidence[], latency_ms, provider}`
> **score** = 风险度（越高越可疑）；**confidence** = 该结论本身的可信度（覆盖率/数据源质量决定）。

### 2.1 E1 引用真实性引擎

| 项 | 内容 |
|---|---|
| **输入** | IR.references、IR.sentences.cites、学科领域、策略配置 |
| **流程** | ① 元数据规范化（DOI/标题清洗、模糊匹配）→ ② 数据源核验 → ③ 存在性/一致性比对 → ④ 引文语义支持度验证 → ⑤ 证据打包 |
| **关键算法/工具** | **元数据**：Crossref / OpenAlex / CNKI / DataCite API（Provider 抽象）；DOI 正则 + title fuzzy match（rapidfuzz ≥90 判同）；Retraction Watch 撤稿检测；**支持度**：claim-citation entailment——将"被引句上下文 + 参考文献标题/摘要"编码，用 NLI 模型（DeBERTa-mnli 微调 / sentence-transformers + 阈值）算 entailment 概率；长引用块做多句对齐（匈牙利匹配） |
| **输出字段** | `metadata_match{found, title_ok, year_ok, venue_ok, doi_valid, source}`; `support_score`（0-1，语义支持度）; `orphan_refs[]`（未被引用）; `missing_refs[]`（引用了但查无此文）; `predatory_venue_flag`; `retracted_flag` |
| **置信度** | `conf = 0.9·found_ratio + 0.1·(1 - fuzzy_margin)`；数据源命中率 <50% 时 conf 置为 0.4 并标注 `low_coverage`（如中文期刊在 Crossref 覆盖低） |
| **证据** | `EV-E1-001 {type:"missing_ref", ref:"[12]", sources:["crossref","openalex"], query:"..."}`、`EV-E1-002 {type:"weak_support", ref:"[3]", nli:0.21, context:"...", ref_abstract:"..."}` |

### 2.2 E2 文本原创性引擎

| 项 | 内容 |
|---|---|
| **输入** | IR.sentences（原文）、可选机构自建库、外部查重 API 开关 |
| **流程** | ① 预处理（去参考文献/致谢/公式、分句、归一化）→ ② 粗筛（SimHash/MinHash LSH 候选）→ ③ 精确匹配（最长公共子串、窗口滑动）→ ④ AIGC 段落级判别 → ⑤ 汇总为文档级两个分值 |
| **关键算法/工具** | **查重**：内部 pgvector/SimHash + 外部 Provider（iThenticate、CNKI、Plagscan 适配器）；开源底座 `simhash`、`text-dedup`；**AIGC**：多特征交叉——perplexity（GPT-2 XL）、burstiness 句长熵、DetectGPT/Logit-Rank 假设采样 + 轻量分类器 + isotonic 温度校准，报告标注 `model_tag + 校准日期` |
| **输出字段** | `plagiarism{doc_score, matched_segments[{sent_ids, source, similarity, url}], self_ref_excluded}`; `aigc{doc_score, para_scores[{para_id, p_ai, ppl, burstiness, logit_rank}], signal_only}` |
| **置信度** | 查重 conf = 1 − 语料库覆盖缺口；AIGC conf <0.6 时强制 `signal_only=true`（非母语作者、专业术语密集文本易误判） |
| **证据** | `EV-E2-001 {type:"matched_segment", src:"arxiv:1706.03762", sim:0.94, quote:"...", offset:[120,189]}`、`EV-E2-002 {type:"aigc_signal", para:"p7", p_ai:0.87, ppl:18.2, burstiness:0.31}` |

### 2.3 E3 图像完整性引擎

| 项 | 内容 |
|---|---|
| **输入** | IR.figures（位图提取，支持 PDF 内嵌图/LaTeX includegraphics） |
| **流程** | ① 解码+EXIF/元数据读取 → ② 感知哈希指纹库查重（跨论文复用）→ ③ 单图篡改取证 → ④ 拼接/复制移动检测 → ⑤ AI 生成检测 → ⑥ 多信号聚合 |
| **关键算法/工具** | **复用**：pHash/dHash（imagehash）+ 汉明距 ≤8 判同，ORB/SIFT 局部特征识别"裁剪/调色后复用"；**篡改**：ELA 误差级分析、CFA 插值一致性、PRNU 噪声残差、复制-移动（块匹配 + ORB）；**拼接**：边缘光照/噪声不连续、频域残差突变；**AI 生成**：XceptionNet 类伪造检测二分类（自部署或商用 API Provider）；标注/曲线图先做 OCR+坐标轴-数值一致性启发式检查 |
| **输出字段** | `reuse[{fig_id, match{paper_id, fig_id, similarity, crop}}]`; `tamper[{fig_id, regions[[x,y,w,h]], method:"ela|copy_move", score}]`; `splice_suspect[{fig_id, score, cue}]`; `ai_generated[{fig_id, p_ai, model, signal_only}]` |
| **置信度** | 每子信号独立 conf；pAI 未校准（ECE>0.1）时 conf=0.5 且 `signal_only=true`；ELA 单独证据不可作结论，需 ≥2 信号一致才提升 risk |
| **证据** | `EV-E3-001 {type:"image_reuse", fig:"f2", matched:"paper_x#f5", phash_dist:4, artifact.overlay_diff}`、`EV-E3-002 {type:"copy_move", fig:"f3", region:[210,80,140,90], score:0.82}` |

### 2.4 E4 逻辑与元数据一致性引擎

| 项 | 内容 |
|---|---|
| **输入** | IR 全量（metadata、references、equations、tables、正文数字断言） |
| **流程** | ① 统计异常 → ② 引用网络异常 → ③ 格式合规 → ④ 内部矛盾扫描 |
| **关键算法/工具** | **统计**：正文报告值 vs 表格/图数值一致性（正则抽取数字 + 单位归一，±0.5% 容差）；描述统计合法性（SD≤0、p=0.000、均值±SD 超量纲、百分比加权≠100）、Benjamini-Hochberg 多重比较提醒；**引用网络**：自引率、文献年龄分布异常、期刊集中度 HHI（>70% 同刊预警）、引用幽灵（复用 E1）、同年同刊异常批量引用（引用堆砌 cartel 检测）；**格式**：CSL 样式渲染比对（APA/IEEE/GB-T 7714）、盲审匿名合规（正文泄露作者/单位）、图表编号连续性、公式引用完整性；**逻辑**：摘要 vs 结论句 NLI 反转检测（conf<0.7 降级为提示） |
| **输出字段** | `stat_anomalies[{id, kind, detail, severity}]`; `citation_net{self_cite_rate, year_span, journal_hhi, implausible_cluster}`; `format{style, violations[{rule, loc, msg}]}`; `internal_contradictions[{s1, s2, type}]` |
| **置信度** | 规则类 = 0.95（确定性）；NLI 矛盾类 = 模型 conf，<0.7 降级为提示 |
| **证据** | `EV-E4-001 {type:"stat_inconsistency", loc:"tab.2 vs 正文L412", claim:"p=0.03", table:"p=0.30"}`、`EV-E4-002 {type:"self_cite_rate", value:0.48, benchmark:"<0.2"}` |

## 3. 融合决策层

### 3.1 证据链聚合

```
输入: E1..E4 的 EngineResult 列表
1. 标准化: 每条 evidence → {id, engine, severity(0..1), confidence, type}
2. 去重/关联: 同一现象多引擎命中 → 组成 evidence_cluster
   （如 E1 缺失文献 + E4 引用网络异常 → cluster "reference_fabrication"）
3. 信号分类:
   - decisive   : 硬证据（查重高相似段、图像与已发表图 pHash 相同、DOI 查无此文）
   - signal     : AIGC 概率、AI 图像概率、统计启发式
   - contextual : 格式违规、风格异常
```

### 3.2 分数融合（加权 + 硬规则双通道）

```
risk_score = Σ w_i · s_i · c_i        # s=引擎score, c=引擎confidence, w 见下
# 权重 w（初始值，按领域配置可调）
E1引用真实 0.30 | E2查重 0.28 | E2.AIGC 0.10 | E3图像 0.22 | E4逻辑 0.10
# AIGC/AI图像权重低，且受 confidence 折扣 —— 体现"信号"定位
```

**伪代码（三级判定）**：

```python
def decide(results: list[EngineResult], policy: Policy) -> Verdict:
    ev   = collect_evidence(results)                    # 全量证据
    risk = weighted_score(results)                      # 融合分
    hard = [e for e in ev if e.type in HARD_RULES]      # 硬规则证据
    sig  = [e for e in ev if e.severity >= 0.75 and e.confidence >= 0.6]

    # —— 硬规则优先，一票触发 ——
    if exists(hard, "image_reuse_confirmed") or exists(hard, "missing_ref_major") \
       or max_matched_plagiarism(results) >= 0.60:
        return Verdict("HIGH", risk, ev, reason="硬证据触发", human_review_required=True)

    if risk >= policy.high_threshold and len(sig) >= 2:      # 严格0.55/标准0.65/宽松0.75
        return Verdict("HIGH", risk, ev, reason="多引擎高严重度信号汇聚", human_review_required=True)

    if risk >= policy.review_threshold or \
       any(e.engine in ("aigc", "ai_image") and e.severity >= 0.8 for e in ev) or \
       any(e.type == "format_block" for e in ev):
        return Verdict("REVIEW", risk, ev, reason="存在需人工确认的信号", human_review_required=True)

    return Verdict("PASS", risk, ev, reason="未达复核阈值")
```

**硬规则表（可配置，一票 HIGH）**：

| 证据类型 | 阈值 | 等级 |
|---|---|---|
| `image_reuse_confirmed` | pHash 相似 ≥0.95 且来源为已发表论文 | HIGH |
| `missing_ref` | DOI/标题经 ≥2 数据源查无此文 | HIGH |
| `plag_segment` | 单源相似 ≥0.60 且跨 ≥3 段 | HIGH |
| `retracted_ref` | 引用已撤稿文献 ≥1 且作为关键依据 | HIGH |
| `stat_fabrication` | 正文与表格数值直接矛盾 | HIGH |
| `plag_segment` | 0.30–0.60 区间 | REVIEW |
| `aigc_signal` | p_ai ≥0.85（仅信号，永不单独触发 HIGH） | REVIEW |
| `self_cite_rate` | >0.50 | REVIEW |

**策略差异**：严格 = 阈值下移 + AIGC/格式权重×1.3；宽松 = 阈值上移 + AIGC 仅在 ≥0.9 时计入。策略随任务落 `policy_snapshot`，历史报告可按快照复算。

### 3.3 解释生成

每条判定产出结构化 `explanation`：`{headline, top_reasons[{cluster, weight_contribution, evidence_ids}], counter_signals[], review_checklist[]}` —— 报告层据此渲染"为什么是这个结论 + 人工应先看哪几条"。

**三级输出**：
- **通过 PASS**：融合分 < 复核阈值且无硬规则命中，附各引擎分数与"未触发原因"。
- **需人工复核 REVIEW**：融合分 ≥ 复核阈值或存在高严重度信号，附复核清单（优先核对的 evidence_ids），人工可确认/推翻并留痕。
- **高风险 HIGH**：硬规则命中或多引擎高严重度信号汇聚，100% 关联人工复核入口，结论必须可回链具体证据。

## 4. 数据模型（PostgreSQL 15 + pgvector）

```sql
documents        (id, owner_id, title, file_uri, file_hash, format(pdf|tex|md|bib),
                  parse_status, domain, created_at)

doc_metadata      (doc_id PK, authors jsonb, abstract, venue, year, doi, extra jsonb)

references        (id, doc_id FK, idx, raw, title, authors, venue, year, doi,
                   external_id, verify_status(unverified|ok|missing|mismatch),
                   verify_source, support_score real, meta jsonb)

figures           (id, doc_id FK, idx, file_uri, phash, width, height, caption, cited_by jsonb)

detection_tasks   (id, doc_id FK, group_id NULL, strategy(strict|standard|loose),
                   status(queued|running|done|failed), progress smallint,
                   enabled_engines text[], policy_snapshot jsonb, callback_url,
                   created_at, started_at, finished_at, error text)

engine_results    (id, task_id FK, engine, engine_version, provider,
                   score real, confidence real, signal_only bool,
                   payload jsonb, latency_ms, status)

evidence          (id, task_id FK, engine_result_id FK, type, severity real,
                   confidence real, cluster_id NULL, quote text, location jsonb,
                   -- location: {"page":3} {"sent_ids":[...]} {"fig_id":"f2","bbox":[...]}
                   source_ref jsonb, artifact_uri jsonb, created_at)

verdicts          (task_id PK, level(pass|review|high), risk_score real,
                   explanation jsonb, policy_snapshot jsonb, reviewed_by NULL,
                   review_note text, reviewed_at)

reports           (id, task_id FK, format(html|pdf|json), uri, created_at)

webhook_deliveries(id, task_id FK, endpoint, payload jsonb,
                   status(pending|sent|failed), retries, last_attempt_at)

-- 向量侧（pgvector，规模化后可迁 Qdrant/Milvus）
sentence_embeddings (sentence_id, doc_id, embedding vector(384))   -- 查重召回
image_embeddings    (fig_id, embedding vector(512))                -- 图像复用检索
ref_embeddings      (ref_id, embedding vector(384))                -- 语义支持度
```

索引：`detection_tasks(status, group_id)`、`evidence(task_id, cluster_id)`、`references(doi)`、`documents(file_hash)`（同文件秒级判重）。

## 5. API 设计

Base: `https://api.example.org/v1`，鉴权 `Authorization: Bearer <api_key>`，幂等 `Idempotency-Key` 头。

### 5.1 提交检测

```http
POST /v1/submissions
Content-Type: multipart/form-data
Idempotency-Key: 7b1c...

file=@paper.pdf
strategy=standard            # strict|standard|loose
domain=computer_science
engines=e1,e2,e3,e4          # 可选，默认全开
enable_external_api=true
callback_url=https://client.example/hook
```

**202 响应**
```json
{"task_id":"tsk_8a21","group_id":null,"status":"queued",
 "links":{"status":"/v1/tasks/tsk_8a21","report":"/v1/tasks/tsk_8a21/report"}}
```

批量：`POST /v1/submissions/batch`（multipart 多文件 或 JSON 数组）→ `{group_id, task_ids:[...]}`。

### 5.2 查询进度

```http
GET /v1/tasks/tsk_8a21
→ 200 {"task_id":"tsk_8a21","status":"running","progress":60,
       "stages":[{"engine":"parse","done":true},
                 {"engine":"e1","done":true},
                 {"engine":"e2_text","done":true},
                 {"engine":"e3","running":true,"est_sec":18},
                 {"engine":"e4","queued":true}],
       "group_id":null}
```

### 5.3 获取报告

```http
GET /v1/tasks/tsk_8a21/report?format=json
→ 200 {
  "verdict":{"level":"review","risk_score":0.68,
             "explanation":{"headline":"3 项高严重度证据待复核",
               "top_reasons":[
                 {"cluster":"image_reuse","contrib":0.22,"evidence_ids":["EV-E3-001"]},
                 {"cluster":"weak_support","contrib":0.18,"evidence_ids":["EV-E1-002"]}],
               "review_checklist":["核对 Fig.2 与来源论文 Fig.5","复核 [7] 引文支持度"]}},
  "engines":[
    {"engine":"e1","score":0.34,"confidence":0.88,
     "evidence":[{"id":"EV-E1-002","type":"weak_support","ref":"[3]","nli":0.21,
                  "context":"...","quote":"..."}]},
    {"engine":"e2_aigc","score":0.71,"confidence":0.55,"signal_only":true,
     "evidence":[{"id":"EV-E2-002","para":"p7","p_ai":0.87,"ppl":18.2}]}
  ],
  "report_pdf":"https://api.example.org/v1/tasks/tsk_8a21/report?format=pdf"
}
```

`format=html|pdf` 返回渲染报告；`?locale=zh-CN` 本地化。

### 5.4 回调通知（Webhook）

```http
POST {callback_url}          # 签名: X-Signature: HMAC-SHA256(body, secret)
{
  "event":"task.completed", "task_id":"tsk_8a21",
  "verdict":"review", "risk_score":0.68,
  "report_url":"https://api.example.org/v1/tasks/tsk_8a21/report",
  "evidence_count":7, "ts":"2025-01-01T00:00:00Z"
}
```
重试：指数退避 5 次（30s/2m/10m/1h/6h），失败进 `webhook_deliveries` 供补发 `POST /v1/webhooks/{id}/retry`。

### 5.5 其他

- `POST /v1/tasks/{id}/review` — 人工复核提交 `{decision:"overturn|confirm", note, evidence_overrides[]}`
- `GET /v1/tasks/{id}/evidence/{eid}/artifact` — 取高亮/overlay 图
- `GET /v1/engines` — 引擎与 Provider 健康状态（可替换性可观测）

## 6. 技术栈建议

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 API | **FastAPI (Python 3.11)** + Pydantic v2 | 异步、OpenAPI 自动生成、类型化 schema |
| 异步队列 | **Celery + Redis**（或 arq/RQ），按 section/figure 分片子任务；flower 监控 | 大文件/批量天然并行，失败重试粒度到引擎 |
| 文档解析 | **GROBID**（PDF→结构化+引文）、pandoc（MD）、pybtex/bibtexparser、latexml/plasTeX（TeX）、tesseract OCR 兜底 | 学术 PDF 解析事实标准 |
| 数据库 | **PostgreSQL 15 + pgvector**（JSONB 存 payload） | 事务 + 向量 + JSON 一库多能，降低运维面 |
| 向量库 | 小规模 pgvector；规模化迁 **Qdrant / Milvus** | 查重候选召回、语义支持度、图像指纹检索 |
| 对象存储 | S3 / MinIO（原文件、图像 artifact、报告） | 大文件不进主库 |
| 缓存/限流 | Redis（外部 API 结果缓存、令牌桶限流） | 同 DOI/同图哈希命中缓存 |
| 图像处理 | OpenCV、imagehash、Pillow、ELA 自实现；AI 检测模型可选 GPU | |
| NLP/AIGC | sentence-transformers、DeBERTa-mnli、GLTR/DetectGPT 特征、isotonic 校准 | |
| 外部 Provider（全部适配器化） | 元数据: Crossref / OpenAlex / DataCite / CNKI；查重: iThenticate/CNKI/自建库；AIGC: 商用 API 或自部署；图像: 商用 deepfake API 或自训模型 | 统一 `Provider` 接口 + 熔断降级 + 结果缓存 |
| 部署 | Docker Compose（dev）→ K8s（按队列深度 HPA） | |

**Provider 抽象（伪代码）**：

```python
class MetadataProvider(Protocol):
    name: str
    def lookup(self, ref: Ref) -> LookupResult: ...   # 返回 found/title_ok/year_ok

registry = {"crossref": CrossrefProvider(), "openalex": OpenAlexProvider(),
            "cnki": CnkiProvider()}
provider = registry[config.metadata_provider]         # 配置切换，零代码改动
```

## 7. 关键风险与缓解

| # | 风险 | 影响 | 缓解措施 |
|---|---|---|---|
| 1 | **误报**（查重误伤合理引用、跨语言同表达、AIGC 误判非母语者） | 冤枉作者、信任崩塌 | ①排除自引/引用/方法学通用句；②AIGC 永远 `signal_only`，高阈值才进 REVIEW；③所有结论附证据+人工复核入口；④按领域校准阈值、用人审结果持续做混淆矩阵监控 |
| 2 | **隐私与合规**（论文未发表、含个人信息/涉密） | 泄密、法律风险 | ①静态加密（SSE）+ TLS1.3；②外部 API 前置**脱敏开关**（默认只送 n-gram 片段/图像哈希而非全文）；③租户级隔离 + RBAC + 全量审计日志；④可配置保留期（默认 90 天自动删除）；⑤GDPR 删除权接口 `DELETE /v1/documents/{id}` |
| 3 | **外部 API 限流/宕机/涨价** | 任务堆积、结论不可用 | ①令牌桶限流 + 指数退避 + 结果缓存（同 DOI/同图哈希命中缓存）；②多 Provider 优先级故障转移（crossref→openalex→本地缓存）；③降级策略：外部不可用 → 该子项 `confidence=0.4, low_coverage`，不阻塞整体；④熔断器 + 健康探针 |
| 4 | **AIGC 检测不确定性**（模型迭代快、改写绕过、校准漂移） | 结论被质疑、无法服众 | ①定位为"信号"，权重 ≤0.10；②报告标注 `model_tag + 校准日期 + 历史准确率`；③多特征交叉（ppl+burstiness+logit_rank）而非单模型；④持续收集人审 ground truth 再校准；⑤明示不确定性区间（p=0.87 → 报告写"中高倾向，需人工确认"） |
| 5 | **图像检测技术极限**（高质量扩散图、语义合理拼接） | 漏报 | 多信号投票（pHash 库 + ELA + 噪声 + AI 分类器），单信号不结论；图像指纹库持续收录已发表论文图 |
| 6 | **解析失败**（扫描版 PDF、复杂 TeX） | 任务失败 | 解析置信度自评，低置信 → `REVIEW` 并提示人工核对解析结果；OCR 兜底（tesseract） |
| 7 | **大规模批量的资源挤占** | SLA 违约 | 队列按优先级分道（interactive/batch）、HPA、子任务级进度上报 |

## 8. 验收标准

### 8.1 功能
- [ ] 支持 PDF / LaTeX / Markdown / BibTeX 四种输入，解析成功率 ≥ 98%（扫描件走 OCR 路径并标注）
- [ ] 四引擎全部可独立开关，单独挂掉不影响其他引擎结果（部分降级 + `low_coverage` 标注）
- [ ] 每条判定均可在报告中定位到 ≥1 条证据（quote/location/artifact 齐全），抽检 100% 可回链
- [ ] 三级判定输出稳定：同一输入 + 同一 policy 版本 → 结果可复现
- [ ] 严格/标准/宽松三策略阈值生效且随 `policy_snapshot` 快照留存
- [ ] 人工复核可覆盖机器结论并留痕（reviewer、note、时间）
- [ ] Webhook 签名验证 + 失败重试 + 手动补发全通

### 8.2 性能
- [ ] 20 页 PDF 标准策略端到端 P50 ≤ 90s、P95 ≤ 5min（不含外部 API 排队）
- [ ] 并发 50 提交不雪崩：队列积压可视化，按队列深度自动扩容
- [ ] 单文件 ≤ 100MB、批量单组 ≤ 200 文件受支持（分片+断点）
- [ ] API p95：提交 <300ms、查询 <200ms、报告 <1s

### 8.3 可解释性
- [ ] 报告包含：融合分、各引擎分/置信度、top 证据簇、反向信号（若有）、人工复核清单
- [ ] AIGC/图像结果显式标注 `signal_only` 与校准信息，不允许单独触发 HIGH
- [ ] 高风险结论 100% 关联人工复核入口与具体 evidence_ids
- [ ] 融合权重/阈值配置版本化，历史报告可复算（给定 policy_snapshot 复现结论）

### 8.4 可扩展性
- [ ] 新增引擎 = 实现 `run(ir, ctx) -> EngineResult` + 注册，不改融合层代码（接口契约测试通过）
- [ ] 新增外部 Provider = 新增适配器类 + 配置项，1 天内可上线切换
- [ ] 引擎独立部署为 worker，可单独扩缩容/换 GPU 资源
- [ ] 回归：黄金样本集（含已知抄袭/已知清白/AIGC 改写集）每版本跑通，指标不回退
