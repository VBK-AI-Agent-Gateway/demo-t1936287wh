01 · 产品定位 & 功能清单

对标钉钉多租户硬性要求SaaS + 私有化

1. 产品定位

维度说明
一句话定位面向 50–5000 人成长型企业的多租户一体化协同办公平台
目标客户成长型企业、连锁门店、制造/零售/教育行业、政企私有化客户

03 · 数据库设计

1. 多租户隔离策略（硬性要求）

层级方案适用说明
必选行级隔离：全业务表带 tenant_id，ORM 强制 WHERE全部租户连接级上下文注入，缺失直接拒绝
可选（大客户）Schema 隔离：每租户一个 schema旗舰/私有化租户级连接池路由
可选（超大/合规）独立库/实例私有化路由表 tenant_id → dsn
缓存key 统一前缀 t:{tenant_id}:*全部禁止跨前缀 SCAN
消息队列topic 租户后缀或消息体携带 tenant_id全部消费端二次校验
文件存储OSS 路径 /{tenant_id}/...全部预签名 URL 短时效

强制约定：任何业务表必须含 tenant_id（除 platform_* 平台级表）；CI 静态检查 + 慢查询审计兜底。

平台级（无 tenant_id）

CREATE TABLE platform_tenant (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(64) NOT NULL,
  slug VARCHAR(32) NOT NULL UNIQUE,
  status TINYINT NOT NULL DEFAULT 1,     -- 1正常 0停用 2试用
  plan VARCHAR(16) NOT NULL DEFAULT 'free',
  quota_user INT NOT NULL DEFAULT 50,
  quota_storage BIGINT NOT NULL DEFAULT 10737418240,
  schema_name VARCHAR(64) NULL,           -- 可选 schema 隔离
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP

组织通讯录

CREATE TABLE org_department (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  parent_id BIGINT NOT NULL DEFAULT 0,
  name VARCHAR(64) NOT NULL,
  path VARCHAR(512) NOT NULL,             -- 物化路径 /1/5/
  leader_id BIGINT NULL, sort INT DEFAULT 0, status TINYINT DEFAULT 1,
  KEY idx_tenant_parent (tenant_id, parent_id),
  KEY idx_tenant_path (tenant_id, path)
);

CREATE TABLE org_user (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  union_id VARCHAR(64) NOT NULL,           -- 租户内唯一
  name VARCHAR(64) NOT NULL,
  mobile_enc VARBINARY(256) NOT NULL,      -- AES 加密
  mobile_hash CHAR(64) NOT NULL,           -- SHA256 索引
  status TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_tenant_union (tenant_id, union_id),
  UNIQUE KEY uk_tenant_mhash (tenant_id, mobile_hash)
);

IM

CREATE TABLE im_conversation_member (

3. 关键机制

3.1 多租户请求链路（隔离硬性要求）

步骤动作
1域名 / Header(X-Tenant) / JWT 中 tenant_id 解析租户
2gateway 校验订阅状态（停用租户 403）
3透传 X-Tenant-Id，写入请求上下文
4ORM 拦截器自动拼 WHERE tenant_id=?，缺失抛异常
5缓存 key、MQ 消息、OSS 路径统一带租户前缀
6审计中间件记录跨租户访问告警

3.2 IM 消息链路

步骤动作
1WS 连接 → 鉴权 → 连接注册表（Redis）
2发消息 → 落库（seq 会话号段）→ Kafka
3在线 WS 直推 + 离线表，登录拉取
4未读数 Redis 维护，已读上报更新 recv_seq

3.3 审批流程引擎

步骤动作
1流程图 JSON（审批人/会签/或签/条件/抄送）
2实例启动 → 状态机推进 → 生成 task
3条件路由 → 全通过写终态
4MQ 事件：扣假期、写工作台待办、IM 提醒
