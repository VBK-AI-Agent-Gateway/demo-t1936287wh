阶段① 产品定位 & 功能清单

1.1 产品定位

维度说明
产品名CloudHub 企业协同办公平台（暂定）
一句话定位对标钉钉的多租户企业协同办公平台，一套代码同时支撑 SaaS 公有云与私有化交付
目标客户20-5000 人规模的中大型企业、政企单位、集团多子公司
核心价值组织在线、沟通在线、业务在线：通讯录+IM+OA 三件套打通，审批与考勤数据回流组织资产
商业模式SaaS 订阅（按活跃用户/月阶梯定价）+ 私有化 License（按节点/模块买断+年维保）
差异化① 租户级强隔离（schema/RLS 双保险）② SaaS/私有化同镜像同版本 ③ 模块可插拔按需开通
竞品对标钉钉、企业微信、飞书、华为 WeLink

3.2 多租户隔离策略（硬性要求）

层级手段说明
L1 应用层所有表强制 tenant_id NOT NULL，MyBatis/JPA 拦截器自动注入 WHERE tenant_id=?应用代码禁止手写无租户条件的查询
L2 ORM 层租户插件 + 单测：任何查询缺 tenant_id 直接抛异常CI 卡点
L3 数据库层RLS（Row Level Security）：ALTER TABLE t ENABLE ROW LEVEL FORCE，会话变量 SET app.tenant_id即便应用有 bug 也无法跨租户读
L4 大客户隔离Schema-per-Enterprise：私有化独立库；SaaS 超大租户可迁独立 schema弹性策略
L5 密钥隔离每租户独立数据密钥 DEK，KMS 包裹存储文件/敏感字段加密
L6 会话隔离JWT 声明 tenant_id，Redis key 前缀 t:{tenant_id}:缓存不串号

RLS 示例：


ALTER TABLE im_message ENABLE FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON im_message
  USING (tenant_id = current_setting('app.tenant_id')::uuid);
-- 业务连接池初始化: SET app.tenant_id = '<tid>';

4.3 关键设计

4.3.1 IM 消息链路

步骤动作
1客户端 WSS 连接 → 网关鉴权(JWT 含 tenant_id/user_id) → 绑定连接
2发送带 client_msg_id，网关分配全局 seq（Redis INCR per conv）
3落库 im_message（分区表）→ Kafka 投递事件
4在线成员实时推送；离线写推送队列（FCM/厂商通道）+ 离线消息漫游
5ACK 回执；未 ACK 指数退避重发；client_msg_id 幂等去重

4.3.2 审批流程执行

步骤动作
1发起：表单校验 → Flowable 启动流程实例（含条件表达式上下文=表单数据）
2生成 oa_task → IM 卡片 + 工作台待办
3审批动作写 oa_task + 流程推进；会签聚合节点等全部完成
4终态回调：请假→att_leave；报销→oa_counter_budget；事件进 Kafka
5全程租户上下文透传，Flowable 任务表加 tenant_id

4.3.3 权限判定链


请求 → Gateway(JWT 校验/租户提取/限流)
     → 业务服务 AOP @PreAuthorize(perm_code)
     → 数据层 MyBatis 租户拦截器 + data_scope(自动生成部门过滤)
     → PG RLS 兜底
     → audit_log 异步落 Kafka

4.3.4 SaaS 与私有化差异

维度SaaS私有化
镜像同一套 K8s 镜像同一套镜像
数据库共享 PG + RLS（大客户可独立 schema/实例）独立 PG
对象存储S3MinIO 内置
注册中心Nacos 集群compose 内置单节点/文件配置
计费/运营模块开关（模块开关 sys_tenant_module）
升级滚动无感升级补丁包 + 回滚脚本
许可证订阅License 文件校验节点数/到期

4.4 容量与高可用

项设计
IM 网关无状态水平扩展，一致性哈希路由会话；单机 50 万长连接
消息扇出群聊广播走网关本地订阅表 + Kafka 分区，避免 DB 轮询
DB主从+流复制，PgBouncer 连接池，每租户连接打标 SET app.tenant_id
降级开关检索、统计、已读回执可独立降级
备份每日全量 + WAL 归档，私有化提供灾备脚本

4.5 安全架构

项措施
传输TLS1.2+，HSTS
数据手机号/证件号字段级 AES-GCM；文件 SSE-KMS 每租户 DEK
认证短信频率限制、密码 Argon2id、MFA(P1)
授权默认拒绝、最小权限；越权测试用例进 CI

附录 · 多租户隔离（硬性要求）

五层防线：应用注入 → ORM 拦截 → PG RLS 强制 → 大客户独立 schema → 每租户独立密钥。任一层失效仍有下一层兜底。

六层隔离矩阵

层级手段兜底价值
L1 应用层tenant_id NOT NULL + 拦截器自动 WHERE主防线
L2 ORM/CI缺租户条件即抛异常，CI 卡点防代码回归
L3 PG RLSFORCE ROW LEVEL SECURITY + SET app.tenant_id库级兜底
L4 Schema/实例超大租户、私有化独立 schema/库物理隔离
L5 密钥每租户 DEK，KMS 包裹泄漏不可解密
L6 会话/缓存JWT 含 tenant_id，Redis key 加租户前缀缓存不串号
